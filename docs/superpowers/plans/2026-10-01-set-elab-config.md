# `setElabConfig` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** leanr elaborates under the oracle's `setElabConfig`
(`foApprox`/`ctxApprox` on), so `Eq.ndrec p h` elaborates as it does in
the oracle.

**Architecture:** `TermElabM::new` applies a pure `set_elab_config`
(a transcription of `Elab/Config.lean:61-62`) to the `MetaCtx` it owns,
through a new additive `MetaCtx::set_config` accessor. This mirrors
`TermElabM.run`'s `withConfig setElabConfig`
(`Elab/Term/TermElabM.lean:2226-2227`). Two oracle-generated corpus
records pin the behaviour.

**Tech Stack:** Rust (`leanr_meta`, `leanr_elab`), Lean
`v4.33.0-rc1` oracle (`dump_elab.lean`), mise tasks.

**Spec:** `docs/superpowers/specs/2026-10-01-set-elab-config-design.md`

## Global Constraints

- The oracle pin stays `leanprover/lean4:v4.33.0-rc1`; do not bump it.
- Fixtures are generated by the oracle only (`mise run fixtures:regen-elab`), never hand-written.
- `leanr_meta/src` changes are limited to the additive, TCB-neutral `set_config` accessor.
- `set_elab_config` sets exactly `fo_approx = true`, `ctx_approx = true`, `const_approx = false`, `quasi_pattern_approx = false`; every other field passes through.
- `ctx_approx` stays inert (the slow `checkAssignmentAux` port is out of scope).
- Run `cargo fmt` (or the full `mise run ci`) before every commit: CI gates on `cargo fmt --check` and clippy.
- Build under `/workspace`, never `/tmp` (`/tmp` is a 20Gi EmptyDir).
- Run `mise run ci` in the foreground and wait for it to finish; do not background it and end the turn.

## Plan-time evidence (already run; do not re-derive)

- The oracle, with `foApprox := false`, rejects both new records:
  `elim/ndrec` with "Application type mismatch", `elim/ndrecExpected`
  with "Type mismatch". With the default elab config it accepts both
  (`Eq.ndrec p h`).
- With `ctxApprox := false` or `foApprox := false`, the oracle gives
  identical output on all 331 existing records.
- leanr **today** fails both new records: `oracle_elab_gate` reports
  `2 divergences`, both `leanr errored: StuckCoercion { .. }`.
- leanr with both flags on passes all 333 records. With `ctx_approx`
  alone it fails both again (`2 divergences`), so `foApprox` is the flag
  that matters.
- The whole `cargo test -p leanr_elab` suite (12 binaries) stays green
  with the flags wired into `TermElabM::new`.
- `with_transparency` and `with_assignable_synthetic_opaque` save and
  restore single fields, and `with_full_approx_def_eq` saves and
  restores the whole `cfg`. All three therefore restore to the elab
  config. `synth_instance_main` installs its own config for the search
  (`synth.rs:2140ff`) and is unaffected.

## Review Focus

1. **A scope that restores the config must restore to the elab config, not to `Config::default()`.** Pinned by Task 1's `term_elab_m_new_applies_elab_config`, together with a `with_transparency` round trip.
2. **`set_elab_config` must pass through every non-approx field.** `univ_approx` defaults to `true`, unlike its siblings, and a struct-literal rewrite could silently reset it. Pinned by Task 1's whole-struct equality test, which starts from a non-default input.
3. **`ctx_approx` alone must not be mistaken for the fix.** Pinned by Task 2's second mutation.
4. **No existing corpus record may change.** Pinned by Task 2's gate run: the floor rises from 331 to 333 and the replay of all 333 must be green.
5. **The bare and expected-type forms are different unification sites** (application argument vs. expected-type propagation). Both get a record in Task 2.

#[cfg(test)]
mod tests {

    use leanr_kernel::Environment;
    use leanr_meta::{Config, EnvExtensions, MetaCtx, TransparencyMode};

    /// Every field the oracle does not touch passes through. The input

        let input = Config {
            transparency: TransparencyMode::Reducible,
            fo_approx: false,
            ctx_approx: false,
            const_approx: true,
            quasi_pattern_approx: true,
            univ_approx: false,
            iota: false,
            ..Config::default()
        };

            fo_approx: true,
            ctx_approx: true,
            const_approx: false,
            quasi_pattern_approx: false,
            ..input
        };

    /// helper restores to it rather than to `Config::default()`.

        let env = Environment::default();
        let view = env.view();
        let mut scratch = Store::scratch();

            view,
            &mut scratch,
            Config::default(),
            EnvExtensions::default(),

        let want = set_elab_config(Config::default());
        assert_eq!(elab.mctx.cfg(), want);
        elab.mctx
            .with_transparency(TransparencyMode::Reducible, |_| ());
        assert_eq!(elab.mctx.cfg(), want);
    }
}
